# 库洛米打卡 · 云同步技术方案

> 状态：已确认（需求核对完成）  
> 技术选型：GitHub（代码）+ Supabase（登录与数据）+ GitHub Pages（网页）

## 1. 目标

网页端与平板 APK **共用同一份云端数据**，双向自动同步。

| 端 | 使用者 | 能力 |
|----|--------|------|
| 平板 APK | 孩子 | 打卡、兑换；敏感操作需家长操作密码 |
| 手机浏览器 | 家长 | 查看进度（须登录） |
| 电脑浏览器 | 家长 | 修改计划、看周报（须登录） |

## 2. 已确认需求摘要

- 全部业务数据上云；必须联网才能改数据；每次操作立刻同步
- 冲突策略：最后修改时间优先（`updated_at`）
- 家长注册账号密码登录，**无需邮箱/手机验证**
- 孩子不注册；多家长可属同一家庭；预留多孩子
- 保留本地 JSON 备份/恢复
- 不做：付费、微信/短信推送、公开社交分享、孩子注册

### 第一版优先级

1. 平板打卡 → 家长马上能看  
2. 电脑改计划 → 平板自动更新  
3. 换机 / 重装不丢数据  
4. 多设备积分与兑换一致  
5. 多家长同家庭  
6. 预留第二个孩子（第一版 UI 可只做一个孩子）

## 3. 系统架构

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  平板 APK   │  │ 手机浏览器  │  │ 电脑浏览器  │
│ (WebView)   │  │ GitHub Pages│  │ GitHub Pages│
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┼────────────────┘
                        │ HTTPS + Supabase JS
                        ▼
              ┌───────────────────┐
              │     Supabase      │
              │  Auth + Postgres  │
              └───────────────────┘

GitHub：源码仓库 + Pages 静态托管（不存打卡业务数据）
```

前端唯一源码在 `web/`；Android 构建时同步进 `assets/`。

## 4. 登录方案（账号 + 密码，无验证）

Supabase Auth 底层仍使用 email 字段，本项目对外表现为「账号」：

| 用户输入 | 内部处理 |
|----------|----------|
| 账号 `xiaoming` | 映射为 `xiaoming@kuromi.local`（仅内部，用户不可见） |
| 密码 | 直接作为 Auth 密码 |

**Supabase 控制台必须关闭「Confirm email」**，注册后立即可用，不发验证邮件。

账号规则（建议）：

- 长度 3–32
- 仅字母、数字、下划线
- 家庭内/全局唯一（由 Auth 唯一性保证）

注册成功后自动：

1. 创建 `families` 记录  
2. 将当前用户写入 `family_members`（role = `owner`）  
3. 创建默认 `children`（如「宝贝」）  
4. 写入空的 `child_state`（对应现有 `defaultState()`）  
5. 引导设置家长操作密码（写入 `parent_pins`）

## 5. 数据模型

详见 [`supabase-schema.sql`](./supabase-schema.sql)。

### 表一览

| 表 | 用途 |
|----|------|
| `families` | 家庭 |
| `family_members` | 家长 ↔ 家庭，含角色 |
| `children` | 孩子（预留多个） |
| `child_state` | 每个孩子的完整业务 JSON + `updated_at` |
| `parent_pins` | 家长操作密码哈希（防孩子乱改） |
| `audit_logs` | 操作审计（可选写入） |

### 为何第一版用整份 JSON

现有前端已是单对象 `state`。云端存整份 JSON + `updated_at`：

- 改动 `storage.js` 成本最低
- 符合「立刻同步 + 最后写入优先」
- 以后若要复杂查询再拆表，不阻塞第一版

## 6. 同步策略

```
本地操作
  → 更新内存 state
  → upsert child_state（state_json, updated_at = now）
  → 成功则可选写 localStorage 作缓存
  → 失败则提示联网/重试，不承诺离线写入

打开/切回前台
  → 拉取云端 child_state
  → 若云端 updated_at 更新 → 覆盖本地并渲染
```

- **必须联网**：无网禁止改数据（需求 Q7 = B）
- **冲突**：以服务端 `updated_at` 较大者为准；并发写入时后到的 upsert 覆盖
- **Realtime（可选 P1 增强）**：订阅 `child_state` 变更，家长端免刷新也能更新

## 7. 权限（RLS）

所有业务表启用 Row Level Security：

- 仅 `family_members` 中的成员可读写本家庭数据
- 孩子无独立 Auth 用户；平板使用家长会话读写对应 `child_id`
- 服务端不信任客户端随意指定他人 `family_id`

## 8. 开发分期

| 阶段 | 内容 |
|------|------|

## 9. 明确不做

- 微信推送 / 短信提醒  
- 社交公开分享  
- 孩子自己注册账号  
- 用 GitHub 仓库当数据库
