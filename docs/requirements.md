# 需求核对纪要

核对方式：逐条问答（2026-09）。以下为最终结论。

## 使用场景

| 端 | 使用者 | 用途 |
|----|--------|------|
| 平板 APK | 孩子 | 每天打卡 |
| 手机浏览器 | 家长 | 查看进度 |
| 电脑浏览器 | 家长 | 修改计划、看周报 |

- 设备规模：可能多平板、多家长（例如 2 平板 + 1 家长，也可能更多）
- 孩子账号：现在一个孩子；以后可能兄弟姐妹各一套（选 C）

## 同步

- **含义**：一端修改 → 云端保存 → 其他端看到同一份最新数据
- 范围：全部业务数据上云
- 方向：双向自动同步
- 冲突：最后修改时间优先
- 离线：必须联网才能改数据
- 频率：每次操作立刻同步

## 账号与安全

- 家长注册账号 + 密码登录；**无需邮箱/手机验证**
- 网页必须登录才能看/改
- 保留「家长操作密码」（改计划等二次验证）+ 登录密码，两套都要
- 孩子不自己注册账号

## 技术

- GitHub：存代码、GitHub Pages 部署网页
- Supabase：登录 + 数据库（免费档起步）
- 不用 GitHub 当业务数据库

## 优先级（第一版）

1. 平板打卡，家长马上能看  
2. 电脑改计划，平板自动更新  
3. 换平板 / 重装不丢数据  
4. 多设备积分、兑换一致  
5. 多家长同家庭登录  
6. 预留第二个孩子结构  

## 明确不做

- 付费订阅 / 内购  
- 微信推送 / 短信提醒  
- 社交分享到公开平台  
- 孩子自己注册账号  

## 数据迁移与备份

- 暂无重要旧数据，可空库起步  
- 保留手动 JSON 备份 / 恢复  

## 登录细节（T1）

- 账号 + 密码即可，不需要验证码 / 邮箱确认  
- 家长注册后即可使用
